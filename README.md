# MedicalDiscImporter 利用ガイド

他院から受け取ったCD・DVDの内容を、Microsoft Defenderでウイルス検査し、ISOイメージの保存とRSBase自動ファイリング形式で出力を行うWindowsアプリです。

RSDicomとほぼ同じ機能ですが、以下の特徴があります。
- スタッフでも操作しやすいよう患者IDを入れて開始を押すだけで全自動実行
- ウイルスチェックを行ってから出力するので、ランサムウェア対策になります（Windows Defenderで検知できないものには無効ですが）
- もとのDiscイメージをISO形式で保存するので、再紹介するときなどDiscのコピーが可能
- 検査日をDICOMファイルから収録するので、検査日でのRSBaseファイリングが可能
- 複数の検査日のデータも、検査日ごとにRSBaseにファイリング

## 1. 設置する端末と配布ファイル

- Windows 11とCD・DVDを読み取れる光学ドライブを用意します。
- `MedicalDiscImporter.exe`を任意の場所にコピーします。.NETランタイムの別途インストールは不要です。
- Microsoft Defenderを`通常稼働`・`リアルタイム保護有効`・`定義更新済み` の状態にします。
- 他社製品などによりDefenderが無効／受動モードの場合は、検査を完了できません。
- WindowsのAutoPlay / AutoRunを無効にし、持ち込まれたディスク内のViewerや実行ファイルは起動しないでください。

導入時は管理者が設定し、日常の取り込みは標準ユーザーで行います。本番利用前に、ダミーデータで検査・共有への保存・RSBase側の取り込みまで確認してください。

## 2. ネットワークの設置（管理者向け）

### インターネット可能ゾーンと電子カルテゾーンを分けている場合

以下は構成例です。実際の接続先・許可範囲は施設のネットワーク管理者と決めてください。

```text
インターネット可能ゾーン／取込用VLAN
  取込端末（本アプリ＋検査サービス）
    ├─ 施設指定の更新経路 → Defender定義・Windows更新
    └─ VLAN間ファイアウォール → 指定共有サーバー：TCP 445
                                  └─ RSBaseが監視する受渡しフォルダ
                                     （電子カルテゾーン／承認済み受渡しゾーン）
```

取込端末は1つの管理されたネットワークに接続し、ゾーン間の通信はルーター／ファイアウォールで制御します。インターネット用Wi-Fiと電子カルテ用LANへの同時接続や、端末上のネットワークブリッジ・インターネット接続共有でゾーンをつながないでください。

| 用途 | 通信の開始元 → 接続先 | 許可する通信 |
|---|---|---|
| ISO・DICOMの共有保存 | 取込端末 → 指定共有サーバー | 通常のWindows共有ではTCP 445（SMB）。送信元・宛先を限定し、戻り通信も許可 |
| Defender更新・クラウド保護 | 取込端末 → 施設指定の更新サーバー／プロキシ／Microsoft接続先 | 採用する更新方式に必要な通信。Microsoft直接接続は主にTCP 443、一部TCP 80 |
| 名前解決・認証など | 取込端末 → 施設指定のDNS・認証基盤など | 共有名・アカウント構成に応じて管理者が設定 |
| 本アプリ → 検査サービス | 同一端末内 | ローカル通信のみ。VLAN間のポート開放は不要 |

**「DICOM送信」は監視フォルダへのファイル配置です。** 本アプリのためにDICOM C-STORE用のポートを開ける必要はありません。RSBaseと電子カルテの連携通信は、別途それぞれのシステムの要件に従います。

- VLANを分けるだけでは共有にアクセスできません。経路、VLAN間の許可、共有サーバーのWindowsファイアウォール、共有権限・NTFS権限をそれぞれ設定します。VLAN間を全面許可せず、必要な端末とサーバーに限定してください。SMBをインターネットへ公開しないでください。
- 共有例は `\\RSBASE-SERVER\Import` です。実際にアプリを使用するWindowsユーザーで接続でき、ファイルの読み書き・作成・名前変更・削除とサブフォルダの作成ができる権限を付与します。共有の認証情報はWindows側で管理し、本アプリには登録しません。
- 検査サービスは同一端末内で検査を担当します。共有先に書き込むのはアプリの実行ユーザーであり、サービスを登録しても共有へのアクセス権は付与されません。
- 電子カルテゾーンからインターネット可能ゾーンへの直接接続を禁止している施設では、承認済みの受渡しサーバー等を使用してください。本アプリ自体にはゾーン間の中継・転送機能はありません。
- インターネットへ直接接続しない端末でも、施設の更新サーバーやオフライン配布などでDefender定義を更新できる運用にします。本アプリは定義更新やプロキシ設定を行いません。
- クラウド保護・自動サンプル送信は、患者情報の取り扱いを含め施設の方針で管理してください。本アプリはこれらの設定を変更しません。

接続先の詳細はMicrosoftの [SMB通信の保護](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-secure-traffic) と [Defenderのネットワーク接続要件](https://learn.microsoft.com/en-us/defender-endpoint/configure-network-connections-microsoft-defender-antivirus) を参照してください。

## 3. ウイルスチェックサービスの登録（初回・管理者作業）

1. 配布用フォルダの `MedicalDiscImporter.exe` を起動し、右上の「設定」を開きます。
2. 「ウイルスチェックサービス」の「サービスを登録」を押します。
3. Windowsの管理者承認に応答します。標準ユーザーの場合は管理者に資格情報の入力を依頼してください。
4. 登録済み・稼働中であることを確認し、「接続を確認」でアプリから通信できることを確認します。
5. PCを再起動し、標準ユーザーで起動して再度接続を確認します。以後、サービスはPC起動時に自動起動します。

接続確認の成功は、ウイルス検査の合格を意味しません。初回はダミーデータを実際に取り込んで確認してください。

サービス名は `MedicalDiscImporter.Defender`、配置先は `%ProgramFiles%\MedicalDiscImporter.ScanService` です。通常のアプリは配布用フォルダから起動してください。

更新時は新しい配布用EXEを起動し、設定でサービスの更新案内を確認します。必要な場合は「サービスを更新」を押して管理者承認を行います。「サービス開始」「サービス停止」「登録を解除」も設定画面から操作できます。これらも管理者承認が必要です。

## 4. 保存先の設定

「設定」で次の項目を入力して「保存」を押します。設定はWindowsユーザーごとに保存されます。

| 設定項目 | 内容 |
|---|---|
| ISO保存先 | ISOを置くローカルフォルダまたはUNC共有（例：`\\RSBASE-SERVER\Import`） |
| RSBase自動取込先 | RSBase / RSDICOM側で監視しているフォルダ |
| DICOM検査名 | DICOM出力名に使用。既定は `CTMRI` |
| ISO検査名 | ISO出力名に使用。既定は `CDROM` |
| Defender定義の有効日数 | 許容する定義の古さ。既定7日、設定範囲1～30日 |
| ディスク自動排出 | 正常完了後に排出する場合にON。既定はOFF |

ISOとDICOMは同じ保存先にできます。別々にする場合、一方がもう一方の配下にならないフォルダを指定してください。

RSBase側でも監視設定が必要です。ISOを取り込む場合はISO拡張子にも対応させ、施設の検査名・命名規則に合うことを確認してください。

## 5. 日常の利用方法

1. CD・DVDを入れ、光学ドライブ欄のディスクマークが**灰色から緑色**に変わることを確認します。隣のディスクラベル・ファイルシステム・容量を確認してください。認識しない場合は「更新」を押します。
2. 取り込み先の患者IDを半角数字で入力します（1～32桁）。
3. 「ISOイメージ」「ウイルススキャン」「DICOM送信」を確認します。通常はウイルススキャンをONにします。スイッチの状態は次回も引き継がれます。
4. 「取込開始」を押し、患者ID・保存先・検査のON/OFFを確認して開始します。
5. 「完了」表示と処理結果を確認します。「DICOM一覧」で内容、「保存先・検査の詳細」で検査結果と保存先を確認できます。
6. RSBase側でも対象患者への取り込み結果を確認し、ディスクを取り出します。

ウイルススキャンがONの場合、検出・検査失敗・結果確認不能では出力しません。OFFにすると**未検査のまま保存・受け渡し**されます。検査エラーの回避目的でOFFにしないでください。検査合格も無害を保証するものではありません。

「DICOM送信」の完了は、監視フォルダへの配置完了を示します。RSBase内部の取り込みや電子カルテへの反映完了は確認していません。入力患者IDは出力ファイル名に使用し、ディスク内のDICOM患者情報そのものは変更しません。

## 6. 困ったとき・データの管理

| 症状 | 確認すること |
|---|---|
| ディスクが認識されない | ドライブの接続・ディスク・選択中のドライブを確認して「更新」 |
| サービスに接続できない | 設定で稼働状態と「接続を確認」。停止中は管理者が「サービス開始」 |
| 検査が完了しない | 詳細の理由、Defenderの状態・定義更新・施設ポリシーを管理者が確認 |
| 保存先に接続できない | 同じWindowsユーザーで共有へ接続できるか、VLAN間通信と共有権限・空き容量を確認 |
| 中止・失敗・一部出力 | 結果詳細と出力済みファイル、RSBase側を確認してから再取り込み。自動再送はありません |
| サービス登録でエラー1072 | Windowsの「サービス」管理画面などを閉じ、削除待ちの解消後に再登録 |

作業データと記録は `%LOCALAPPDATA%\MedicalDiscImporter\Quarantine`、設定は `%LOCALAPPDATA%\MedicalDiscImporter\settings.json` に保存されます。患者情報を含むため、アクセス権・保管期限・削除方法は施設で決めてください。失敗・中止時も作業データは自動削除されません。

保存先の `.MedicalDiscImporter` フォルダは採番・排他制御用です。削除・移動しないでください。再取り込みは別の出力になり、重複する可能性があります。

ISOはWindowsから読み取れるファイルをまとめ直したものです。原本のセクタ・トラック等を完全に複製する用途には対応していません。

開発・ビルド・検査仕様は [開発・実装資料](docs/DevelopmentGuide.md)、開発計画は [実装計画](docs/ImplementationPlan.md) を参照してください。
